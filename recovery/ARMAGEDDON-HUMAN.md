# Армагеддон — инструкция для человека

Читать, когда сервера нет. Без терминального жаргона. Всё, что нужно, — это
новый сервер, доступ к домену и три файла, которые хранятся **вне** старого сервера.

---

## Что должно лежать вне сервера (проверь сегодня, а не в день аварии)

1. **Пароль шифрования снимков** — в менеджере паролей, не на сервере.
2. **Ключ провайдера модели** (DeepSeek) — там же.
3. **Доступ к домену** (логин регистратора, NS).
4. **Адрес бакета со снимками** и ключ к нему.
5. Этот файл и `ARMAGEDDON-LLM.md` — распечатаны или в том же менеджере.

Нет любого пункта — восстановление встанет именно на нём.

---

## Шаг 1. Новый сервер (10–20 минут)

Любой VPS: Debian 13, 4 ядра, 8 ГБ памяти, 60 ГБ диска. Хостер неважен —
лишь бы давал root по ключу.

Получил IP и root-пароль — сразу смени пароль на ключ, это две команды, Пиксель
подскажет в `pixel doctor`.

## Шаг 2. Поставить Пикселя (2 минуты)

На новом сервере:

```
apt update && apt install -y nodejs npm python3 git curl
git clone https://github.com/Archakovss/pixel.git
cd pixel && ./install.sh
```

Клонировать приватный репозиторий — по токену, он у тебя в менеджере паролей.

## Шаг 3. Дать Пикселю ключ (1 минута)

```
echo 'КЛЮЧ_DEEPSEEK' > ~/.pixel/provider.key
chmod 600 ~/.pixel/provider.key
pixel doctor
```

`doctor` покажет список: что есть, чего нет. Красные пункты — доустановить
(`apt install postgresql nginx`). Пока `doctor` не позеленел, дальше не идти.

## Шаг 4. Подъём (20–40 минут)

```
pixel
```

Дальше Пикселю можно сказать словами:

> Восстанови Ядро по карточке Армагеддона. Снимок самый свежий. Спрашивай, если
> нужно решение.

Он прочитает `recovery/ARMAGEDDON-LLM.md`, проверит снимок, развернёт базу,
поднимет процессы, настроит сайт и покажет проверку по шагам.

## Шаг 5. Проверка (5 минут)

- Открыть `https://fridaybot.ru/core/health` — должно быть `ok: true`, а
  `loaded_commit` и `head` совпадать.
- Открыть панель, зайти в чат, отправить сообщение.
- Открыть один клиентский сайт.
- Написать в Telegram-бота.

Не совпало — не «подождать», а сказать Пикселю, какой именно пункт не сошёлся.

---

## Чего НЕ делать

- Не восстанавливать поверх работающего сервера «на всякий случай».
- Не менять DNS до того, как новый сервер отдаёт `/health`.
- Не гнать `rm -rf` и `DROP` руками из паники: снимок цел, базу можно развернуть заново.
- Не доверять зелёной галочке без открытия сайта: проверяется только потребителем.
