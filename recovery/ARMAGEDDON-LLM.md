# Армагеддон — регламент для агента

Ты — Пиксель. Твоя задача: поднять Ядро на новой машине. Действуй по шагам,
после каждого — проверка. Не переходи дальше, пока проверка не зелёная.

## Законы этого регламента

1. **Проверка важнее скорости.** «Команда прошла» ≠ «работает». Проверяй на границе
   потребителя: `/health`, открытая страница, ответ бота.
2. **Ничего необратимого без человека.** Удаление данных, смена секретов, DNS,
   публикация — только после явного «да».
3. **Идемпотентность.** Каждый шаг можно повторить. Повтор не должен ломать сделанное.
4. **Не догадываться.** Не знаешь, где снимок или какой домен — спроси, а не выдумывай.
5. **Не восстанавливать поверх живого.** Сначала проверь, не работает ли уже.

## Шаг 0. Домен (проверить первым)

```bash
dig +short fridaybot.ru A
curl -sI --max-time 5 https://fridaybot.ru/core/health | head -1
```

Если домен не резолвится или отдаёт чужой сертификат — восстановление на этом домене
невозможно. Спроси человека: есть ли запасной домен и доступ к регистратору.

Запасной домен: `DOMAIN=<домен>` при запуске `restore.sh` — подменит `server_name`.
После подъёма перечисли человеку, что осталось переключить: DNS, OAuth redirect,
Telegram webhook, S3 CORS, ссылки в письмах. Не отчитывайся «готово», пока
`https://<домен>/core/health` не отвечает `ok: true`.

## Шаг 0. Осмотр (2 минуты)

```bash
pixel doctor
```

Ожидаемо: node ≥ 20, curl, git, psql, pm2, nginx — зелёные. Красное — доустановить:

```bash
apt update && apt install -y nodejs npm python3 git curl postgresql nginx
```

Проверка: `pixel doctor` без ✖ (tmux и pm2 могут быть красными до установки Ядра).

## Шаг 1. Секреты и доступ (без этого дальше нельзя)

Нужны: ключ провайдера (`~/.pixel/provider.key`), пароль шифрования снимков,
ключ S3, доступ к домену. Все — от человека. **Не запрашивай их в открытом виде
в чат**, проси положить в файл.

Проверка: `test -r ~/.pixel/provider.key` и ключ реально отвечает (шаг 2).

## Шаг 2. Модель (1 минута)

```bash
pixel "ответь одним словом: связь есть"
```

Ожидаемо: ответ. Если 401 — ключ неверный. Если «сеть: fetch failed» — нет выхода
в интернет. Дальше не идти: поднимать нечем.

## Шаг 3. Снимок (5–20 минут)

```bash
# список снимков
aws --endpoint-url=https://storage.yandexcloud.net s3 ls s3://<bucket>/dr/
```

Выбрать самый свежий **целый** (все части на месте, размер совпадает с манифестом).
Скачать в `~/.pixel/restore/`, расшифровать паролем человека.

Проверка: архив распаковывается, внутри `manifest.json`, дампы БД, список pm2-приложений.

**Стоп-условие:** манифест не сходится или частей меньше — не восстанавливать,
доложить человеку: «снимок битый, нужен предыдущий».

## Шаг 4. База (5–10 минут)

```bash
systemctl enable --now postgresql
sudo -u postgres psql -c "CREATE ROLE core LOGIN PASSWORD '<из секретов>';"
sudo -u postgres createdb -O core platform
psql "postgresql://core:<пароль>@127.0.0.1:5432/platform" -f restore/platform.sql
```

Проверка: `psql ... -c "\dt"` — таблицы на месте; количество строк в 2–3 ключевых
таблицах совпадает с манифестом (с допуском на сутки).

## Шаг 5. Код и процессы (10–15 минут)

```bash
git clone <репозиторий Ядра> /root/orencode
cd /root/orencode && npm ci --omit=dev
pm2 start ecosystem.config.js      # или по списку из манифеста
pm2 save && pm2 startup
```

Проверка: `pm2 list` — все `online`; `curl -s 127.0.0.1:3212/health` — `ok: true`
и `loaded_commit == head`.

**Стоп-условие:** процесс падает в цикле — читать `pm2 logs <имя> --lines 50`,
не «перезапускать пока не поднимется».

## Шаг 6. Сайт и TLS (10 минут)

```bash
cp -a restore/nginx/* /etc/nginx/sites-available/ && ln -sf ... sites-enabled/
nginx -t && systemctl reload nginx
certbot --nginx -d fridaybot.ru -d <остальные домены>
```

Проверка: `curl -sI https://fridaybot.ru/core/health` — 200 и валидный сертификат.

## Шаг 7. Приёмка (5 минут)

- `curl https://fridaybot.ru/core/health` → `ok`, `stale: false`.
- Открыть панель, отправить сообщение в чат.
- Один клиентский сайт открывается.
- Telegram-бот отвечает.

Отчёт человеку: что поднято, что нет, сколько заняло, что осталось.

## Чего не делать никогда

- `rm -rf` по каталогам данных ради «чистой установки».
- `DROP DATABASE` без подтверждения — даже если «кажется, что мусор».
- Менять DNS до зелёного `/health`.
- Копировать секреты в чат, в логи, в git.
- Говорить «готово» без пройденной приёмки (шаг 7).
